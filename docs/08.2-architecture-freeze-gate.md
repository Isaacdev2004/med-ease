# Backend Architecture Freeze Gate

**Med-ease Enterprise Healthcare Platform**  
**Gate position:** After Document 08.2 — Before Phase 08.3  
**Status:** ✅ **APPROVED** — 2026-07-15

---

## Purpose

Enterprise healthcare systems treat the data model as a **contract**. Changing schema, tenancy boundaries, or repository mappings after implementation begins causes expensive migrations, frontend/backend drift, and compliance re-certification.

This gate required explicit approval of all structural decisions before any Prisma schema, NestJS module, or API endpoint is written.

**Gate is closed for architecture. Implementation phase is open.**

## What is frozen

| Category                | Frozen elements                                             | Change process                                                           |
| ----------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------ |
| **Schema layout**       | PostgreSQL schemas (`core`, `clinical`, `operations`, etc.) | ADR + architect approval                                                 |
| **Shared Kernel**       | `tenants`, `users`, `patients`, `providers`, `facilities`   | ADR only — highest bar                                                   |
| **Tenancy**             | `tenant_id` + RLS model                                     | ADR + security review                                                    |
| **Table names**         | All tables in entity registry                               | Additive only; renames forbidden post-freeze                             |
| **Repository methods**  | Methods in contract matrix                                  | Additive endpoints OK; signature changes require frontend adapter update |
| **Permission strings**  | 500+ from frontend config                                   | Frozen — backend enforces exact strings                                  |
| **Pagination envelope** | `{ items, total, page, pageSize }`                          | Frozen                                                                   |
| **API prefix**          | `/api/v1`                                                   | Frozen                                                                   |
| **Error format**        | RFC 7807 Problem Details                                    | Frozen                                                                   |

## What is NOT frozen

| Category                   | Notes                                          |
| -------------------------- | ---------------------------------------------- |
| **Additive columns**       | New nullable columns with migration review     |
| **New indexes**            | Performance tuning                             |
| **New repository methods** | Must update contract matrix + OpenAPI          |
| **Seed data**              | Dev/staging only                               |
| **Implementation details** | Service logic, caching TTLs, queue concurrency |

## Post-freeze change control

1. Propose change via ADR in `docs/adr/`
2. Impact analysis: frontend types, migrations, RLS, FHIR mapping
3. Architect + security approval
4. Update entity registry, data dictionary, contract matrix if affected
5. Implement via forward migration only
